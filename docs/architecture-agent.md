# Агент-менеджер: долгосрочная архитектура

> [!NOTE]
> Цель — самостоятельный менеджер, который годами ведёт клиентов: помнит всё, что делал и что клиент присылал, переиспользует материалы, выполняет любые поручения (от карточек до поиска и исследований), продаёт разовые заказы и ежемесячную подписку «личный ассистент», проверяет оплату и сообщает о ней. Владелец подключается только когда нужно.

## Принципы

1. **Модель — без состояния, память — в базе.** Никаких долгоживущих CLI-сессий: каждый ход агент получает собранный контекст клиента. Клиент написал через месяц — контекст тот же.
2. **Агент решает, код гарантирует.** Агент работает инструментами; правила (вилка цен, лимиты отправки, один счёт на заказ, согласие на фото, квота подписки) зашиты внутри инструментов, а не в промпте.
3. **Дешёвая модель ведёт диалог, сильные — выполняют.** Оператор по умолчанию — DeepSeek V4.1 Flash (1 млн контекста, видит картинки); исполнители берут свои модели.
4. **Всё документируется.** Память, файлы, деньги и действия агента видны владельцу и лежат в папке клиента.

## Слои

```

                    ↓
┌──────────── Клиент (Client) ──────────────┐
```

## Память клиента

| Слой | Что хранит | Кто пишет |
|---|---|---|
| Факты | устойчивые сведения: ниша, аккаунты, предпочтения, договорённости, кто что решает | агент (`remember`) + вспомогательная модель после диалога |
| Эпизоды | сжатые саммари отрезков переписки (каждые ~30 сообщений или после паузы) | вспомогательная модель |
| Файлы | всё, что прислал клиент и что мы сделали: фото, документы, результаты, превью — с подписью и тегами | автоматически; подписи — модель со зрением |
| Сообщения | полная переписка | автоматически |

**Поиск по памяти — локальный и мультимодальный.** Векторы считает [EmbeddingGemma 2](https://huggingface.co/onnx-community/embeddinggemma-2-ONNX) (Google, Apache 2.0, 768 измерений, текст и картинки в одном пространстве) прямо в приложении через transformers.js на CPU, без внешних сервисов. Проверено на Mac mini: загрузка из кэша 3,6 с, текст ~0,5 с на 1000 символов, картинка 7–19 с, память ~1,3 ГБ — поэтому модель живёт в отдельном потоке, индексирует в фоне и выгружается в простое. Векторы лежат в SQLite рядом с данными клиента; поиск гибридный: полнотекстовый (FTS5) + косинусное сходство, только внутри одного клиента.

**Контекст хода:** активные факты → последние 3 эпизода → последние 30 сообщений → открытые заказы и подписка → файлы, найденные по последнему сообщению (полнотекстовый поиск) → каталог услуг. Общий бюджет токенов ограничен.

## Деньги

- **Заказы** — разовая работа по вилке цен (уже есть).
- **Подписка «личный ассистент»** — тариф с ценой в месяц и квотой поручений; период, статус (активна / ждёт оплаты / отменена), напоминание за 3 дня, счёт на продление через ЮKassa. Автосписание — позже (нужно одобрение ЮKassa).
- **Журнал платежей** — каждый платёж клиента (заказ или подписка), статус проверяется у ЮKassa; агент через `payment_status` честно отвечает «оплачено / ждём / не прошло».

## Поручения ассистента

Исполнитель `assistant`: поиск в интернете (Tavily) → чтение страниц → синтез с источниками → результат в Markdown, при необходимости файл. Для подписчиков — в пределах квоты, для остальных — разовый заказ.
